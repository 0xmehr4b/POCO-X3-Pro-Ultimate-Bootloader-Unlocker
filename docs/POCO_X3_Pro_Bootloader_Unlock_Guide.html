1. Why Official Mi Unlock Fails with Error 20091 & 20031

Many POCO X3 Pro (vayu / bhima, Snapdragon 860 / SM8150) devices have had their SoC reballed or replaced with an unfused SM8150 chip (reporting secure: no in Fastboot).

  • Why Settings → Mi Unlock Status returns 20091: Settings.apk (CloudDeviceStatus.bindAccountWithDevice) asks Qualcomm TEE (cardapp) to sign the bind request using the factory FID key. On an unfused replacement CPU, cardapp fails with Error 41, Xiaomi's server responds No available key on server, and Settings.apk hardcodes error_code = 20091.
  • Why EDL 9008 Needs Zero Xiaomi Auth on secure: no: Disassembly of prog_ufs_firehose_sm7150_ddr.elf (at 0x14839868 → 0x1483d904) confirms that the programmer checks boot_is_auth_enabled(). When secure: no, it returns 0 and completely bypasses Xiaomi's EDL <sig> authentication.
  • Why Patching devinfo Permanently Unlocks abl.elf: At boot (0x2b4e4), abl.elf checks IsSecureBootEnabled(); when 0, it skips oem_misc1 token checks and trusts devinfo byte 0x0D (is_unlocked = 1) and byte 0x0E (is_unlock_critical = 1).

5. Post-Unlock First Boot & Troubleshooting Guide

1. Phone Shows Charging Icon / Red Bar After EDL Reset:
If the phone shows an empty battery/plug icon with a red bar underneath after EDL reset, the Battery connector is not fully clicked down. Unplug USB, press the Battery connector firmly onto the motherboard socket until it clicks, then hold the Power button for 5 seconds. You will see the POCO logo with the Unlocked padlock icon at the top!
2. Phone Enters Xiaomi Default Recovery Mode After Unlock:
On Android 12+, Qualcomm Keymaster (km41) binds the /data encryption key to the bootloader lock state (device_locked). When transitioning from Locked (1) to Unlocked (0), you must format /data once (just like official Mi Unlock does):
In Xiaomi Recovery, select Wipe Data → Wipe All Data → Confirm, then select Reboot to System.
